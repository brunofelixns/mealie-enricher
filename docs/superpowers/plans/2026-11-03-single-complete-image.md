# Single complete image implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish one image containing BEDCA under the normal version and latest tags.

**Architecture:** Root Dockerfile imports BEDCA in a build stage and produces a
complete final image. Release helpers use one image digest, while trusted security
tools still accept historical dual-image manifests.

**Tech Stack:** Python, Docker Buildx, Compose, DuckDB, GitHub Actions/Release Please.

**Spec:** `docs/superpowers/specs/2026-11-03-single-complete-image.md`

## Global Constraints

- One multi-platform published candidate; no new version-bedca image variants.
- Keep immutable historical tags and old release recovery working.
- Preserve source CSVs, NOTICE, read-only catalog and user 1000.
- Maintain full CI, image scanning, SBOMs and signed promotion provenance.
- Continue the session's inline implementation on a dedicated branch.
- Existing authorization covers protected PR merge and publishing the new version.

## Review Focus

- Partial tag promotion must be repairable without moving newer aliases.
- A legacy manifest must not be mistaken for a malformed single-image manifest.
- Default Compose must not override the image with an absent catalog path.
- A historical release checkout must remain valid under trusted current CI tools.
- An arbitrary file in the BEDCA named context must never enter the image.

**Files:** `ci/images.py`, `ci/security.py`, `tests/unit/test_ci_images.py`,
`tests/unit/test_ci_security.py`.

**Interfaces:** Add `publication_images(manifest)` returning named image digests;
consume it in promotion, scanning and provenance. New manifests use image_digest;
old base_digest/bedca_digest manifests retain their behavior.
