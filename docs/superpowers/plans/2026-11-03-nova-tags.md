# NOVA tags implementation plan

**Goal:** Add optional NOVA recipe tags using OpenAI Decisions and the already configured key.

**Architecture:** A bounded choice classifier uses the existing Decisions credentials,
model, confidence threshold, timeout and concurrency settings. Tagging persists an
assessment in recipe extras and applies one NOVA tag alongside the current tags.
`NOVA_ENABLED` is independent of catalog matching and defaults to false.

**Recipe policy:** This is an application estimate, not an official NOVA rating of
a mixed dish. Choose the highest evidenced processing group of an ingredient,
except that culinary group 2 ingredients do not raise a group 1 home preparation
to group 2 or 3. Group 2 applies when only culinary ingredients are represented.
Missing composition or conflicting evidence must allow `needs_context`.

**Constraints:** Preserve manual nutrition, personal tags, ingredients and API
contracts. Do not fetch product matches or infer processing from nutrients.
Use `NOVA:1` through `NOVA:4`, or `NOVA:Desconocida`. Cache outcomes by recipe
evidence and classifier configuration; do not loop on self-generated webhooks.
Forced estimation can retry unknown outcomes. Recipe text is untrusted data.

## Review focus

- Malformed/boolean/nonfinite confidence must never become a known NOVA group.
- Missing ingredient data must remain unknown without a provider call.
- Changes to instructions must invalidate NOVA even when the legacy nutrition
  hash is unchanged, without overwriting manually entered nutrition.
- Provider failures and refusals must not break nutrient estimation or cause
  an endless webhook patch cycle.
- Automatic tag replacement must preserve personal tags, extras and recipe text.

## Execution notes

The user authorized key reuse and asked to continue implementation in this
checkout. Work proceeds here, with tests before production changes; no remote
Mealie backfill, publication or deployment is part of this change.

Final verification: `pytest -q --cov=mealie_enricher --cov-report=term-missing
--cov-fail-under=95` passed with 562 tests, 27 opt-in skips and 96.18% coverage.
Ruff check/format, mypy and source Compose validation passed. Windows asyncio
requires local loopback access, so async tests ran outside the restricted sandbox.

Independent code review found one tag-identity defect: an unresolved NOVA tag
must not claim the last resolved nutrition tag's slug or index an empty list.
Two regressions reproduced this before the fix; both are in the final green suite.
An unavailable tag is recorded explicitly and does not create a self-webhook loop.

Live Decisions checks used five synthetic recipes and the authorized existing
key: groups 1, 2 and 3 were accepted; an ambiguous sauce abstained, and a drink
example at confidence 0.71 was correctly rejected by the 0.9 threshold. Group 4
acceptance is covered with the simulated official transport. Production Mealie
behavior and generalized classification accuracy remain outside this local
verification; Mealie workflow tests use controlled HTTP transports.
